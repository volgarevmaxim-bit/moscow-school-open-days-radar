# Техническое задание: радар дней открытых дверей в школах Москвы (MVP, v4 — финал уточнений)

Документ заменяет v3. Все открытые вопросы из v3 закрыты. Изменения ниже.

## 1. Цель проекта

Еженедельно автоматически формировать и отправлять в Telegram сводку по заданному списку школ:
- анонсы дней открытых дверей / мероприятий для родителей и детей, которые ещё не являются учениками школы — в структурированном виде (дата, адрес, регистрация) со ссылкой на исходное сообщение;
- заголовки прочих сообщений школы — без извлечения деталей, только заголовок + ссылка на оригинал;
- явное сообщение об отсутствии дней открытых дверей за неделю (heartbeat-сигнал).

## 2. Границы MVP (Scope)

- **Upstream: только Telegram.**
- **Downstream (v1): Telethon-клиент отправляет сводку в Saved Messages того же аккаунта.** Отдельный выделенный чат — backlog v2.
- **Реестр школ**: за основу — `schools_normalized.csv` из [`volgarevmaxim-bit/schools-map-mathex`](https://github.com/volgarevmaxim-bit/schools-map-mathex).
- **Периодичность upstream-чтения**: раз в сутки. **Периодичность сводки**: раз в неделю.

## 3. Подготовка реестра школ

### 3.1 Ручные исключения — закрыто
Исключить по имени: Brookes Moscow Early Years (Pre-Nursery, Nursery), дошкольные группы Cambridge International School, Школа «Президент», Павловская гимназия, Wunderpark International School. Присутствие всех пяти подтверждено пользователем визуально на карте (географически вне зоны интереса, оттуда и скопирован список) — дополнительная проверка через API не требуется.

### 3.2 Фильтр «сад / приём с 1 класса» через сопоставление с `places.json` — закрыто
Метка `kind` (`green`=сад, `blue`=приём с 1 класса, `red`=остальное) переносится из `places.json` в `schools_normalized.csv` через сопоставление по имени и адресу (оба файла содержат оба поля). В реестр для радара попадают только записи с итоговой меткой `blue`.

**Что делать с несопоставленными записями (закрыто пользователем):** пользователь проверил `places.json` — у всех имеющихся там записей метка `kind` присутствует, проблема может быть только в отсутствии самой записи-пары для части строк `schools_normalized.csv`. Решение: такие несопоставленные школы **не включаются в активный мониторинг v1** и выносятся в отдельный список технического долга на v2 (см. раздел 9), чтобы не блокировать запуск.

## 4. Архитектура

```
[schools_normalized.csv] → исключения по имени → [сопоставление kind с places.json, blue-only] → [Финальный реестр школ v1]
        │                                                  │
        │                                                  └→ [несопоставленные записи → backlog v2]
        ▼
[Автоматическое сопоставление школа → TG-канал]  ── агент, критерии в п.5
        │
        ▼
[Реестр каналов: school_id, name, tg_username, match_confidence]
        │
        ▼
[Upstream: Telethon userbot, раз в сутки]
  - iter_messages по каждому каналу
  - сравнение с state (last_seen_id)
        │
        ▼
[LLM-классификация+условная экстракция]  ── DeepSeek V4.1 Flash, zero-shot, без regex
  если сообщение — анонс мероприятия для будущих учеников/родителей:
        → строгий JSON: {school_id, event_date, address, registration_required, message_link}
  иначе:
        → {school_id, headline, message_link}
        │
        ▼
[State: GitHub Actions Cache/Artifacts]
        │  (раз в неделю)
        ▼
[LLM-суммаризация]  ── тот же DeepSeek V4.1 Flash, без few-shot
  - блок 1: дни открытых дверей (или явный текст "не было")
  - блок 2: заголовки прочих сообщений по школам, со ссылками
        │
        ▼
[Downstream: Telethon → Saved Messages]
```

## 5. Критерии уверенности для сопоставления школа → Telegram-канал — уточнено

Основной («идентифицирующий») признак:
- Если у школы есть числовой номер — совпадения номера в username/названии/описании канала **достаточно самостоятельно**.
- Если номера нет (школа с собственным именем, например «Вторая школа») — нужно совпадение **минимум двух ключевых слов** из названия.

Дополнительный (подтверждающий) признак — хотя бы один из:
- слово «официальный» (или явный эквивалент) в описании канала;
- контекст Москвы, видимый в ленте публикаций.

**Адрес школы как критерий не используется** — на практике адреса в описании/ленте Telegram-каналов обычно нет (проверено на примере `t.me/school_1537`).

**Правило принятия решения:** идентифицирующий признак совпал **и** есть хотя бы один подтверждающий → высокая уверенность, агент подтверждает сам. Идентифицирующий признак не совпал или подтверждающих нет вовсе → случай на подтверждение пользователю.

Если автоматический поиск через Telethon не даёт результата вообще, пользователь передаёт отдельным потоком залогиненную веб-сессию суб-агенту, который выполняет поиск через неё и возвращает результат.

## 6. Технологический стек

| Компонент | Технология |
|---|---|
| Upstream-клиент | Python, Telethon |
| Оркестрация | GitHub Actions: суточный cron (чтение) + недельный cron (суммаризация+отправка) |
| Хранение состояния | GitHub Actions Cache/Artifacts |
| Классификация/экстракция/суммаризация | DeepSeek V4.1 Flash, единая модель, вызовы в off-peak окно |
| Downstream (v1) | Telethon → Saved Messages |
| Секреты | GitHub Secrets: Telethon StringSession, DeepSeek API key |

**Off-peak расписание:** пиковые часы DeepSeek — 01:00–04:00 и 06:00–10:00 UTC по будням (04:00–07:00 и 09:00–13:00 МСК); всё остальное время, включая выходные — off-peak (вдвое дешевле). Рекомендуемое окно для обоих cron-джобов — вечер по Москве (20:00–23:00 МСК).

## 7. Схемы данных

**Реестр школ после фильтрации** (`schools_filtered.json`):
```json
{"id": "forbes-high-10", "name": "Павловская гимназия", "included": false, "reason": "manual exclusion"}
{"id": "mathex-shkola-1535", "name": "Школа 1535", "included": true, "kind_match": "blue", "kind_source": "places.json fuzzy match"}
```

**Реестр каналов** (`schools_channels.json`):
```json
{"school_id": "1537", "name": "Школа №1537", "tg_username": "school_1537", "match_confidence": "high", "match_reason": "number match + Moscow context in feed"}
```

**Классификация сообщения — "мероприятие для будущих учеников":**
```json
{"school_id": "1537", "category": "open_house", "event_date": "2026-10-02", "address": "...", "registration_required": true, "message_link": "https://t.me/school_1537/1234"}
```

**Классификация сообщения — "прочее":**
```json
{"school_id": "1537", "category": "other", "headline": "Мос-волонтёр: уборка осенних листьев", "message_link": "https://t.me/school_1537/1230"}
```

**Еженедельная сводка (пример):**
```
За прошедшую неделю сообщений о планируемых днях открытых дверей в анализируемых школах не было.

Прочие сообщения:
Школа 1537: о спортивных достижениях (https://t.me/school_1537/1229);
Мос-волонтёр — уборка осенних листьев (https://t.me/school_1537/1230);
открытый мастер-класс для учеников и их родителей (https://t.me/school_1537/1231).
```

## 8. Этапы разработки

1. **Разбор реестра**: загрузить `schools_normalized.csv`, применить 5 ручных исключений, выполнить сопоставление по имени/адресу с `places.json`, отфильтровать по `blue`, несопоставленные записи — в backlog v2 (не в активный мониторинг).
2. **Сопоставление с каналами**: агент ищет каналы по уточнённой схеме (п.5), пользователь проверяет случаи без подтверждающего признака.
3. **Калибровочный прогон**: прогнать классификацию на архиве сообщений за прошлый год по 1–2 каналам, посмотреть, как модель справляется без few-shot и regex, скорректировать промпт при необходимости.
4. **Upstream + state**: Telethon-чтение раз в сутки, state в GitHub Actions Cache.
5. **Классификация**: интеграция DeepSeek V4.1 Flash, строгая JSON-схема для open_house, заголовок+ссылка для остального.
6. **Суммаризация и отправка**: недельная агрегация, отправка в Saved Messages, оба cron-джоба — в off-peak окно.
7. **Безопасность**: alter-ego аккаунт уже найден — настроить и залогинить сессию, StringSession только в Secrets.

- Отдельный выделенный чат для сводки вместо Saved Messages.
